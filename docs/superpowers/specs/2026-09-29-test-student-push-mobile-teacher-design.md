# 테스트 학생 알림 및 교사 모바일 화면 설계

## 목적

교사가 전체 학생 알림을 켜지 않고도 이름이 정확히 `테스트`인 학생의 등록 기기에 실제 수면·카페인 푸시 알림을 보낼 수 있게 한다. 동시에 현재 PC 중심 교사 대시보드를 같은 URL에서 모바일 화면에도 맞게 재배치한다. 기존 학생 기록, 교사 기능, PC 레이아웃, Apps Script 시트 연결은 유지한다.

## 범위

### 포함

- 교사 인증 뒤 사용할 수 있는 테스트 학생 연결 상태 조회
- 이름이 정확히 `테스트`인 학생에게만 수동 시험 알림 전송
- 수면 알림과 카페인 알림을 각각 시험하는 교사 UI
- 성공·만료·실패 집계 표시와 안전한 오류 문구
- 교사 대시보드 전체의 768px 이하 및 480px 이하 반응형 레이아웃
- 데스크톱과 모바일 회귀 검증

### 제외

- 실제 학생을 임의로 선택하는 기능
- 전체 학생 일괄 시험 발송
- 시험 알림을 위한 별도 비밀번호 또는 별도 명단
- 학생·교사용 별도 모바일 URL
- 기존 건강 기록 데이터나 배지 기준 변경

## 1. 테스트 학생 알림

### 대상 결정

브라우저는 학번, 구독 ID, 푸시 endpoint 또는 암호화 키를 시험 발송 요청에 포함하지 않는다. Apps Script가 현재 시트의 학생 명단에서 공백을 제거한 이름이 정확히 `테스트`인 행을 찾는다.

- 일치하는 학생이 0명이면 `테스트 학생을 찾을 수 없음`으로 실패한다.
- 일치하는 학생이 2명 이상이면 `테스트 학생이 중복됨`으로 실패한다.
- 유일한 학생의 학번은 서버 내부에서만 사용한다.
- 이름이 `테스트1`이거나 `테스트 학생`인 계정은 대상에 포함하지 않는다.

이 규칙으로 실제 학생 학번을 잘못 선택하거나 브라우저 요청을 변조해 다른 학생에게 보내는 것을 차단한다.

### 구독 조건

시험 대상은 `푸시구독` 시트에서 다음 조건을 모두 만족하는 행이다.

- 역할이 `student`
- 학생 학번이 서버에서 찾은 테스트 학생과 일치
- 활성 상태가 참
- 선택한 알림 유형의 학생 선호가 참

학생이 로그인만 하고 `알림 켜기`와 브라우저 권한 허용을 하지 않았다면 등록 기기 수는 0으로 표시한다. 수면 또는 카페인 알림을 개별적으로 꺼 둔 경우 해당 유형의 시험 발송 대상에서도 제외한다.

### 서버 흐름

기존 `/api/teacher/reminders/[...path].js` catch-all 아래에 `test-student` 경로를 추가해 Vercel Hobby 함수 수를 늘리지 않는다.

- `GET /api/teacher/reminders/test-student`
  - 교사 세션을 확인한다.
  - Apps Script에 테스트 학생 대상 요약을 요청한다.
  - 브라우저에는 학생 이름 `테스트`, 수면 가능 기기 수, 카페인 가능 기기 수만 반환한다.
- `POST /api/teacher/reminders/test-student`
  - 교사 세션을 확인한다.
  - 본문은 `{ type: "sleep" | "caffeine" }`만 허용한다.
  - Apps Script가 유일한 테스트 학생과 해당 유형 구독을 다시 확인해 최소 전송 자료를 Vercel 서버에 반환한다.
  - Vercel 서버가 기존 Web Push 발송기와 승인된 알림 문구를 사용해 전송한다.
  - Apps Script에 결과를 기록하고 브라우저에는 대상·성공·만료·실패 개수만 반환한다.

브라우저 응답과 로그에는 endpoint, p256dh, auth, 전체 시트 ID, 공유 비밀값을 포함하지 않는다. 전송 결과는 기존 알림 발송 로그 형식에 수동 시험임을 구분할 수 있는 중복 방지 키로 저장하며, 정규 예약 발송의 중복 판정과 충돌하지 않는다. 만료 응답을 받은 구독은 기존 정책대로 비활성화한다.

### 교사 UI

`🔔 알림 설정` 탭의 현재 교사 브라우저 시험 영역과 구분되는 `테스트 학생 알림 확인` 카드를 추가한다.

- 연결 상태 새로고침
- `테스트 · 수면 가능 기기 N대 · 카페인 가능 기기 N대`
- `수면 알림 보내기`
- `카페인 알림 보내기`
- 결과: `대상 N · 성공 N · 만료 N · 실패 N`

버튼은 요청 중 비활성화해 중복 클릭을 막는다. 대상 기기가 0대이면 발송 버튼을 비활성화하고 학생 화면에서 앱 설치, `알림 켜기`, 브라우저 알림 허용을 완료하라는 안내를 표시한다. 전체 학생 알림 설정이 꺼져 있어도 수동 시험은 가능하다.

### 오류 처리

- 교사 세션 만료: 다시 로그인 안내
- 테스트 학생 없음 또는 중복: 발송 없이 명확한 관리자 안내
- 해당 유형 구독 없음: 학생 기기 설정 안내
- Push 만료: 실패 집계 후 해당 구독 비활성화
- 일시적 제공자 오류: 일반 오류 문구와 실패 집계만 표시
- Apps Script 오류: 내부 응답이나 민감정보를 노출하지 않고 처리 실패로 표시

## 2. 교사 대시보드 모바일 반응형

### 기본 원칙

별도 모바일 페이지를 만들지 않고 기존 `/teacher` DOM과 기능을 유지한 채 CSS 반응형 규칙과 필요한 최소 래퍼만 보완한다. PC 1024px 초과 레이아웃은 유지한다. 모바일에서도 건강 데이터와 설정 항목을 생략하지 않는다.

### 헤더와 도구

- 제목, 설명, 최근 업데이트를 자연스럽게 줄바꿈한다.
- 768px 이하에서는 데스크톱 화면 비율 슬라이더를 숨기고 실제 화면 배율을 100%로 고정한다.
- 자동 새로고침 주기와 데이터 새로고침을 두 개의 간결한 모바일 행으로 배치한다.
- 교사 로그아웃 버튼을 화면 우하단 고정 위치에서 헤더 작업 영역으로 이동해 카드와 겹치지 않게 한다.

### 탭

- 탭 바는 한 줄 가로 스크롤과 스크롤 스냅을 사용한다.
- 각 탭은 축소되지 않으며 아이콘과 이름 전체가 표시된다.
- 활성 탭 밑줄과 접근성 상태는 유지한다.
- 탭 바는 긴 페이지에서 찾기 쉽도록 모바일 상단에 고정할 수 있으나 콘텐츠를 가리지 않게 헤더 높이를 반영한다.

### 카드, 필터, 표

- 대시보드·설정·학생 카드는 768px 이하에서 한 열을 기본으로 한다.
- 작은 통계 묶음만 2열을 사용하고 480px 이하에서는 필요하면 1열로 전환한다.
- 학생 카드는 학번·이름·카페인·수면 상태가 화면 밖으로 밀리지 않도록 행을 줄바꿈한다.
- 조회 기간 버튼, 학년·반 선택, 검색 필드는 화면 폭에 맞춰 줄바꿈하고 터치 높이를 확보한다.
- 반별 기간표와 알림 기간표는 모바일에서 각 반을 한 개의 카드형 행으로 표시하며 날짜 입력은 전체 폭을 사용한다.
- 넓은 분석표는 의미 있는 열을 숨기지 않고 표 컨테이너 안에서만 가로 스크롤한다.
- 그래프는 카드 폭에 맞추되 축 정보 보존이 필요한 경우 그래프 내부만 가로 스크롤한다.

### 설정 화면

- 설정 섹션 제목과 보조 설명이 잘리지 않게 줄바꿈한다.
- 숫자·날짜·선택 입력은 모바일에서 전체 폭을 사용한다.
- 배지 카드와 수면 기준은 한 열로 쌓고 내부 라벨·입력·단위를 줄바꿈한다.
- 저장 버튼은 섹션 상단 또는 하단에서 전체 폭으로 쉽게 누를 수 있게 한다.

### 접근성과 조작성

- 주요 버튼과 탭의 최소 터치 높이는 44px을 목표로 한다.
- 가로 스크롤 영역에는 화면 전체가 옆으로 밀리지 않도록 `min-width: 0`과 자체 overflow를 적용한다.
- 고정 요소가 입력창, 카드 또는 브라우저 하단 UI를 가리지 않게 한다.
- 기존 키보드 포커스, 색상 상태, 텍스트 정보는 유지한다.

## 보안 및 개인정보

- 시험 발송 대상은 서버가 이름 `테스트`로 확정하며 브라우저 제공 식별자를 신뢰하지 않는다.
- 푸시 구독 endpoint와 키는 Apps Script와 Vercel 서버 사이에서만 이동한다.
- 공개 코드와 브라우저 응답에는 교사 비밀번호, 시트 ID, Apps Script URL, 공유 비밀값을 넣지 않는다.
- 교사 세션 없이는 상태 조회와 시험 발송 모두 401로 거절한다.
- 일반 학생 선택 또는 전체 발송으로 확장되는 요청은 거절한다.

## 검증 계획

### 자동 검증

- Apps Script: 테스트 학생 0명·1명·중복, 유형별 선호, 활성·비활성·다중 기기 조회
- API: 교사 인증, 허용 본문, 학생 ID·구독 ID 주입 거절, 집계형 응답, 만료·실패 처리
- 라우터: 기존 catch-all의 `test-student` 경로 연결과 함수 수 제한
- 브라우저 로직: 상태 조회, 버튼 비활성화, 유형별 발송, 중복 클릭 차단, 오류 표시
- 보안 검사: 공개 번들 및 응답에 구독 키와 서버 비밀값이 없음
- 기존 Node/API/Apps Script 전체 회귀 테스트

### 화면 검증

- 390×844 및 412×915: 헤더, 탭, 필터, 학생 목록, 알림 설정, 배지 설정, 수면 설정
- 768px: 태블릿 전환점
- 1440px 이상: 기존 PC 레이아웃 회귀
- 화면 전체의 가로 overflow 부재
- 탭 이름, 입력값, 버튼, 로그아웃이 잘리거나 겹치지 않음

### 운영 검증

1. 테스트 학생 기기에서 로그인하고 앱 설치, 알림 켜기, 수면·카페인 선호를 허용한다.
2. 교사 화면에서 테스트 학생의 유형별 기기 수를 확인한다.
3. 수면 시험 알림과 카페인 시험 알림을 각각 전송한다.
4. 테스트 학생 기기에서 시스템 알림 수신과 눌렀을 때 해당 기록 화면 이동을 확인한다.
5. 전체 학생 알림이 꺼진 상태이고 다른 학생에게 전송되지 않았는지 확인한다.

## 완료 기준

- 이름이 정확히 `테스트`인 유일한 학생에게만 시험 알림이 전달된다.
- 다른 학생 식별자를 브라우저에서 주입해도 발송되지 않는다.
- 전체 학생 알림을 켜지 않고 수면·카페인 실제 알림을 시험할 수 있다.
- 첨부 화면에서 보인 탭 잘림, 가로 overflow, 로그아웃 겹침, 넓은 설정표 문제가 모바일에서 해소된다.
- PC 화면과 기존 기록·조회·설정 기능에 회귀가 없다.
