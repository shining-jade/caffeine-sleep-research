# 카페인·수면 모니터링 시스템 Vercel 보안 배포 설계

작성일: 2026-09-28  
상태: 사용자 설계 승인 후 구현 전 검토본

## 1. 목적

학생과 교사가 학교 Google 계정 없이 Vercel 공개 URL에서 카페인·수면 모니터링 시스템을 이용하게 한다. Apps Script는 브라우저 화면을 제공하지 않고 현재 연구용 Google 시트에 데이터를 저장하고 조회하는 백엔드로만 사용한다.

이번 단계의 성공 조건은 다음과 같다.

- 학생 화면이 Vercel 주소의 `/`에서 직접 열린다.
- 교사 화면이 같은 Vercel 주소의 `/teacher`에서 직접 열린다.
- 학생이 학번과 이름으로 로그인하고 자신의 기록을 저장·조회할 수 있다.
- 교사는 별도 비밀번호로 로그인한 뒤 연구 데이터를 조회할 수 있다.
- 교사 비밀번호, 시트 ID, 학생 건강 데이터가 공개 GitHub 코드나 브라우저 JavaScript에 포함되지 않는다.
- 실제 학생 기록 제출이 현재 연구용 시트에 저장되고 교사 화면에서 조회되는 것을 확인한다.
- 기존 학생·교사 기능과 현재 챌린지·뱃지 기능은 이번 배포 전환에서 동작을 보존한다.

## 2. 확인된 현재 상태

- 현재 GitHub Pages의 `main`은 학생 앱을 호스팅하지 않고 Apps Script 웹 앱으로 이동시키는 짧은 리디렉션 페이지다.
- 로그인된 Chrome에서는 리디렉션된 Apps Script 주소에 계정 경로가 붙으며 “현재 파일을 열 수 없습니다” 오류가 재현됐다.
- 현재 Apps Script 활성 배포는 소유자 권한으로 실행되고 “모든 사용자”에게 공개되어 있으며, 비로그인 연결 점검 요청에는 정상 응답한다.
- Apps Script 원본은 `Code.gs`, `index.html`, `teacher.html`로 구성되어 있다.
- 학생·교사 HTML에 포함된 Apps Script 배포 주소는 현재 활성 배포 주소와 다르다.
- 공개 GET 라우터의 허용 목록에 학생 기능뿐 아니라 교사용 조회·변경 기능도 포함되어 있다.
- 현재 연구용 시트에는 `students`, `ai_reports`, `teacher_messages`, `caffeine`, `sleep`, `info`, `inquiries`, `teacher_awards`, `caffeine_db`, `teacher's monitoring`, `항목` 탭이 있다.
- 원격 저장소의 기존 `secure-api` 및 `student-frontend` 브랜치에는 학생 HTML과 브리지 초안이 있으나, Vercel 서버 인증 계층과 교사 화면 배포는 구현되어 있지 않다.

## 3. 선택한 구조

```text
학생 브라우저 ─┐
               ├─ HTTPS ─> Vercel 앱/API ─ HTTPS + 서버 비밀값 ─> Apps Script ─> 현재 Google 시트
교사 브라우저 ─┘
```

Vercel은 화면과 인증 경계를 담당한다. Apps Script는 현재 시트의 데이터 연산만 담당한다. 브라우저는 Apps Script URL이나 시트 ID를 알 필요가 없고 직접 호출하지 않는다.

### 3.1 공개 경로

- `/`: 기존 학생 화면
- `/teacher`: 기존 교사 대시보드와 로그인 화면
- `/api/student/login`: 학번·이름 확인 및 학생 세션 발급
- `/api/student/logout`: 학생 세션 종료
- `/api/student/action`: 학생에게 허용된 데이터 작업
- `/api/teacher/login`: 교사 비밀번호 확인 및 교사 세션 발급
- `/api/teacher/logout`: 교사 세션 종료
- `/api/teacher/action`: 교사에게 허용된 데이터 작업
- `/api/health`: 개인정보를 반환하지 않는 연결 상태 확인

## 4. 인증과 비밀정보

### 4.1 Vercel 환경 변수

다음 값은 Vercel 프로젝트의 Production 및 Preview 환경 변수로만 관리한다.

- Apps Script 활성 배포 URL
- Vercel과 Apps Script 사이의 공유 비밀값
- 교사 비밀번호 검증값
- 세션 서명 키

환경 변수의 실제 값은 채팅, Git 커밋, 브라우저 코드, 로그에 출력하지 않는다.

### 4.2 Apps Script 속성

다음 값은 Apps Script의 Script Properties에만 둔다.

- 현재 연구용 스프레드시트 ID
- Vercel과 공유하는 백엔드 비밀값
- 기존 Gemini API 키 등 서버 전용 설정

Apps Script는 `getActiveSpreadsheet()`에 의존하지 않고 Script Property의 현재 시트 ID를 읽어 `SpreadsheetApp.openById()`로 연다. 속성이 없거나 대상 ID가 예상과 맞지 않으면 쓰기 작업을 거부한다.

### 4.3 세션

- Vercel은 학생과 교사에게 역할이 포함된 서명 세션을 `HttpOnly`, `Secure`, `SameSite=Lax` 쿠키로 발급한다.
- 학생 세션에는 정규화된 학생 식별자와 이름만 넣고 만료 시간을 둔다.
- 교사 세션에는 교사 역할과 만료 시간만 넣는다.
- 로그아웃 시 쿠키를 만료한다.
- 브라우저의 `localStorage`에는 비밀번호나 장기 인증 토큰을 저장하지 않는다.

학생의 학번·이름 인증은 기존 사용성을 보존하지만, 두 값을 아는 사람이 학생을 사칭할 가능성까지 제거하지는 못한다. 이번 범위에서는 로그인 이후 다른 학생의 식별자를 임의로 요청하는 행위를 서버에서 차단한다.

## 5. 권한과 데이터 소유권

Vercel의 학생 API는 학생 세션의 학번과 이름을 신뢰 원본으로 사용한다. 브라우저가 보낸 학번은 무시하거나 세션 값과 다르면 거부한다.

- 학생 조회: 세션 학생의 데이터만 반환한다.
- 학생 저장: payload의 학번과 이름을 세션 값으로 덮어쓴다.
- 학생 수정·삭제: 기록 ID에 연결된 학번이 세션 학번과 같은지 Apps Script에서 확인한다.
- 문의, 메시지, 뱃지 확인: 행 번호나 기록 ID만으로 처리하지 않고 학생 소유권을 함께 확인한다.
- 교사용 작업: 유효한 교사 세션이 있을 때만 Vercel이 Apps Script에 전달한다.
- Apps Script: 올바른 백엔드 공유 비밀값이 없는 모든 데이터 요청을 거부한다.

Apps Script는 역할별 허용 작업 목록을 둔다. 학생 목록에는 학생 화면에서 실제로 사용하는 함수만 포함하고, 교사 목록에는 대시보드에 필요한 함수만 포함한다.

## 6. Apps Script 진입점

- 데이터 API는 `doPost(e)` 하나로 통일한다.
- JSON 본문에는 `action`, `params`, `role`, 백엔드 공유 비밀값을 전달한다.
- `doGet(e)`는 개인정보 API나 기존 학생·교사 HTML을 제공하지 않는다. 개인정보를 반환하지 않는 안내 또는 상태 응답만 제공한다.
- URL 쿼리 문자열로 학번, 이름, 비밀번호, 세션 또는 건강 데이터를 전달하지 않는다.
- 오류 응답은 내부 시트명이나 비밀값을 노출하지 않는 공통 형식을 사용한다.
- 로그에는 비밀번호, 세션, 전체 요청 본문, 학생 건강 데이터가 남지 않게 한다.

기존 활성 배포는 새 코드 버전으로 갱신한다. 현재 프로젝트 밖의 오래된 배포 주소는 새 Vercel 코드에서 사용하지 않는다.

## 7. 화면 보존과 전환

Apps Script의 기존 `index.html`과 `teacher.html`을 기준으로 공개 정적 자산을 분리한다. 기존 입력 양식, 차트, 통계, 문의, 메시지, AI 분석, 뱃지 화면을 보존하되 `google.script.run` 호출은 같은 출처의 Vercel API 클라이언트로 교체한다.

초기 화면 동작은 다음과 같다.

1. 학생 화면은 세션 확인 후 로그인 또는 기존 대시보드를 표시한다.
2. 교사 화면은 인증 성공 전까지 전체 명단과 기록 요청을 실행하지 않는다.
3. 세션 만료 응답을 받으면 민감한 화면 데이터를 지우고 로그인 화면으로 돌아간다.
4. 네트워크 및 Apps Script 오류는 사용자가 재시도할 수 있는 일반 메시지로 표시한다.

## 8. 챌린지와 뱃지 범위

이번 배포 전환에서는 기존 챌린지 기간, 달성 조건, 뱃지 설정, 교사 승인 데이터를 변환하거나 초기화하지 않는다. 관련 호출은 인증된 학생·교사 API를 통해 기존 결과를 유지하도록 연결한다.

7일 챌린지의 기간, 달성 기준, 연속·누적 판정, 뱃지 종류 및 승인 방식 변경은 Vercel 연결이 검증된 다음 별도 설계와 테스트로 진행한다. 이 분리는 연결 오류와 챌린지 판정 오류를 독립적으로 추적하기 위한 것이다.

## 9. 저장소와 배포

- 공개 GitHub 저장소 `caffeine-sleep-research`를 Vercel 프로젝트의 소스로 계속 사용한다.
- GitHub Pages는 Vercel 운영 검증이 끝난 뒤 비활성화한다. 저장소 자체는 삭제하지 않는다.
- `main` 브랜치 push를 Vercel Production 자동 배포와 연결한다.
- Pull Request 또는 작업 브랜치는 Vercel Preview에서 먼저 검증한다.
- 환경 변수는 Vercel UI에 직접 설정하고 커밋하지 않는다.
- Apps Script 코드는 프로젝트 편집기에서 변경·저장·새 버전 배포한다. Apps Script 변경만으로 GitHub나 Vercel 배포가 자동 실행되지는 않는다.

## 10. 테스트 전략

### 10.1 자동 테스트

- 세션 서명, 만료, 변조 거부
- 학생·교사 역할별 허용 작업
- 학생 payload의 학번 강제 덮어쓰기
- 타 학생 기록 ID 수정·삭제 거부
- 비로그인 교사 API 거부
- Apps Script 공유 비밀값 누락·불일치 거부
- Apps Script 오류의 안전한 변환
- 공개 번들 및 Git 추적 파일의 비밀번호·시트 ID·학생 데이터 문자열 검사

### 10.2 배포 전 통합 확인

- Vercel 학생 URL이 Google 로그인 없이 열린다.
- Vercel 교사 URL이 Google 로그인 없이 로그인 화면까지 열린다.
- Apps Script 상태 요청이 Vercel 서버를 통해 성공한다.
- 브라우저에서 Apps Script URL과 비밀값이 노출되지 않는다.

### 10.3 실제 데이터 흐름 확인

사용자가 제공하거나 승인한 테스트 학생 계정으로 다음을 확인한다.

1. 학생 로그인
2. 구분 가능한 테스트 기록 제출
3. 현재 연구용 시트의 올바른 탭에 새 행 저장 확인
4. 학생 화면에서 해당 기록 조회 확인
5. 교사 로그인
6. 교사 화면에서 같은 기록 조회 확인

검증용 기록은 실제 연구 데이터와 구분 가능한 값으로 만들며, 검증 후 삭제가 필요하면 삭제 직전에 사용자 확인을 받는다.

## 11. 배포 완료 조건

다음 조건이 모두 충족되어야 학생·교사 URL을 완료 결과로 전달한다.

- 로컬 자동 테스트와 빌드 성공
- Preview 환경에서 학생·교사 인증 및 권한 확인
- Apps Script 새 버전 배포 성공
- Production 환경 변수 설정과 Production 배포 성공
- 비로그인 브라우저에서 두 화면 접근 성공
- 학생 제출이 현재 시트에 저장됨을 확인
- 교사 로그인 후 해당 기록 조회 성공
- 공개 저장소와 브라우저 번들에서 비밀정보가 검출되지 않음
