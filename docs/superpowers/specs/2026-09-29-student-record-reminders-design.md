# 카페인·수면 기록 푸시 알림 설계

## 1. 목적

학생이 5주간 카페인·수면 기록을 꾸준히 남길 수 있도록, 기록이 없는 경우에만 휴대폰 푸시 알림을 보낸다. 학생과 교사는 학교 Google 계정 없이 기존 Vercel 주소를 계속 사용한다. Apps Script는 현재 Google 시트의 저장·조회 게이트웨이 역할을 유지하고, 예약 실행과 푸시 발송은 Vercel 서버에서 담당한다.

성공 조건은 다음과 같다.

- 아이폰과 안드로이드에서 홈 화면 앱 설치 방법을 학생이 실제 화면형 안내로 따라 할 수 있다.
- 학생이 명시적으로 허용한 기기에만 알림을 보낸다.
- 아침에는 전날 밤 수면 기록, 저녁에는 당일 카페인 기록이 없는 학생만 알림 대상이 된다.
- `섭취 안 함` 기록은 카페인 기록 완료로 인정한다.
- 교사는 반별 운영기간과 전 학급 공통 알림 시간을 설정할 수 있다.
- 학생은 아침·저녁 알림을 각각 끌 수 있다.
- 학생 개인정보와 푸시 구독 비밀값이 공개 코드나 브라우저 설정에 노출되지 않는다.

## 2. 확정된 사용자 경험

### 2.1 로그인 화면의 설치 안내

학생 로그인 화면에는 기존 버튼 아래에 다음 버튼을 추가한다.

`📲 앱 설치·알림 설정 방법`

버튼을 누르면 현재 기기와 브라우저를 감지하여 단계별 안내창을 표시한다.

- 아이폰: Safari에서 열기 → 공유 → 홈 화면에 추가 → 홈 화면 아이콘 실행 → 로그인 → 알림 허용
- 안드로이드 Chrome: 메뉴 → 앱 설치 또는 홈 화면에 추가 → 설치된 아이콘 실행 → 로그인 → 알림 허용
- 삼성 인터넷: 현재 페이지 추가 → 홈 화면 → 로그인 → 알림 허용
- 네이버 앱 내부 브라우저: Safari 또는 Chrome으로 다시 열도록 안내

안내는 단순 문장 목록이 아니라 브라우저 툴바, 메뉴 항목, 홈 화면 아이콘, 알림 허용창을 휴대폰 화면처럼 보여 주는 단계형 모달로 제공한다. 안드로이드에서 `beforeinstallprompt`를 사용할 수 있으면 `지금 앱 설치하기` 버튼을 제공한다. 아이폰에서는 브라우저 정책상 설치창을 프로그램으로 강제할 수 없으므로 화면 안내만 제공한다.

설치는 선택 사항이다. 설치하지 않은 학생도 기존 웹주소에서 기록할 수 있다.

### 2.2 알림 신청과 학생 설정

홈 화면 앱으로 로그인한 학생에게 다음 안내를 보여 준다.

- 제목: `카페인·수면 기록 알림 받기`
- 설명: `기록을 잊지 않도록 아침에는 수면, 저녁에는 카페인 기록을 안내해 드려요. 이미 기록했다면 알림을 보내지 않아요.`
- 기본 동작 버튼: `알림 켜기`
- 보조 문구: `알림은 언제든 설정에서 끌 수 있어요.`

브라우저의 알림 권한 요청은 반드시 학생이 `알림 켜기`를 누른 뒤 실행한다. 권한을 거절한 경우 반복해서 시스템 권한창을 띄우지 않고, 설정 화면에서 다시 허용하는 방법만 안내한다.

학생 설정 화면에는 다음 항목을 제공한다.

- `카페인·수면 기록 알림`
- `아침 수면 기록 알림 · 오전 설정 시각`
- `저녁 카페인 기록 알림 · 오후 설정 시각`
- 두 알림의 개별 켜기/끄기
- 휴대폰 알림 권한 상태
- 앱 설치 및 권한 설정 안내 다시 보기

학생의 선택은 기기 구독별로 저장한다. 한 학생이 여러 기기를 등록할 수 있으며, 각 기기에서 개별적으로 알림을 끌 수 있다.

### 2.3 푸시 알림 문구와 이동

아침 알림:

- 제목: `좋은 아침이에요 ☀️`
- 본문: `어젯밤 수면 기록을 간단히 남겨보세요.`
- 누르면 수면 기록 화면으로 이동한다.

저녁 알림:

- 제목: `오늘의 기록을 돌아볼 시간이에요 🌙`
- 본문: `오늘의 카페인 기록을 확인해 주세요. 마시지 않았다면 ‘섭취 안 함’을 선택하면 돼요.`
- 누르면 카페인 기록 화면으로 이동한다.

잠금화면 알림에는 학번, 이름, 카페인 섭취량, 수면시간, 미기록 횟수를 표시하지 않는다. 소리·진동·배너·잠금화면·집중모드 적용 여부는 학생의 휴대폰 운영체제 설정이 최종 결정한다.

## 3. 교사 관리자 설정

교사 설정 화면에 `카페인·수면 기록 알림 설정` 영역을 추가한다.

### 3.1 설정 항목

- 알림 기능 전체 켜기/끄기
- 수면 알림 켜기/끄기
- 카페인 알림 켜기/끄기
- 1·2·3·4반별 운영 시작일과 종료일
- 전 학급 공통 수면 알림 시각
- 전 학급 공통 카페인 알림 시각
- 주말 포함 여부
- 확정 문구 미리보기

무료 Vercel 예약 실행의 정밀도를 고려해 시간은 정시 단위로 선택한다. 기본값은 오전 8시와 오후 8시다. UI에는 `선택한 시간대 안에서 발송될 수 있습니다`라고 안내한다.

### 3.2 운영 상태

- 알림을 허용한 학생 수와 활성 기기 수
- 반별 활성 구독 수
- 마지막 예약 실행 시각
- 대상 학생 수, 발송 성공 수, 만료 구독 수, 실패 수
- 다음 예정 수면·카페인 알림 시간
- 교사 기기용 시험 알림 등록 및 보내기

시험 알림은 교사 자신의 현재 브라우저에만 보낸다. 실제 학생에게 시험 알림을 보내는 기능은 포함하지 않는다.

## 4. 기술 구조

### 4.1 PWA 구성

Vercel 공개 파일에 다음 항목을 추가한다.

- Web App Manifest: 앱 이름, `id`, `start_url`, `scope`, `display: standalone`, 아이콘
- Service Worker: 푸시 수신, 알림 표시, 알림 클릭 처리
- 설치 상태와 푸시 기능 지원 여부를 확인하는 브라우저 모듈
- 아이폰용 `apple-touch-icon` 및 관련 메타데이터

서비스워커는 알림 클릭 시 이미 열린 학생 화면을 우선 활성화하고, 없으면 다음 딥링크를 연다.

- 수면: `/?open=sleep&date=YYYY-MM-DD`
- 카페인: `/?open=caffeine&date=YYYY-MM-DD`

로그인 복구가 끝난 뒤 딥링크를 적용한다. 로그인되지 않은 경우 먼저 로그인 화면을 보여 주고, 로그인 성공 후 원래 기록 탭으로 이동한다.

### 4.2 서버 API

학생 API:

- `GET /api/student/push/config`: 공개 VAPID 키와 현재 알림 설정 시각 조회
- `POST /api/student/push/subscribe`: 현재 학생 세션에 구독 등록
- `GET /api/student/push/preferences`: 현재 기기 설정 조회
- `POST /api/student/push/preferences`: 아침·저녁 설정 변경
- `POST /api/student/push/unsubscribe`: 현재 기기 구독 비활성화

교사 API:

- `GET /api/teacher/reminders/config`: 관리자 설정과 운영 상태 조회
- `POST /api/teacher/reminders/config`: 관리자 설정 저장
- `POST /api/teacher/reminders/test-subscribe`: 교사 시험 기기 등록
- `POST /api/teacher/reminders/test-send`: 현재 교사 기기로 시험 알림 발송

예약 API:

- `GET /api/reminders/run`: Vercel Cron 전용 실행

학생·교사 API는 기존 서명 세션을 사용한다. 예약 API는 Vercel의 `CRON_SECRET` Authorization 헤더를 검증한다. 브라우저가 학생 학번을 요청 본문에 넣더라도 서버는 세션의 학생 ID로 덮어쓴다.

### 4.3 VAPID와 환경변수

표준 Web Push와 VAPID를 사용한다.

- `WEB_PUSH_VAPID_PUBLIC_KEY`: 브라우저 구독용 공개키
- `WEB_PUSH_VAPID_PRIVATE_KEY`: Vercel 서버 전용 비밀키
- `WEB_PUSH_SUBJECT`: 관리자 연락용 URI
- `CRON_SECRET`: 예약 API 보호용 비밀값

비밀키와 구독 인증키를 GitHub에 커밋하지 않는다. VAPID 공개키만 브라우저에 전달한다.

### 4.4 Apps Script 역할

Apps Script는 현재와 같이 시트 저장·조회 게이트웨이로만 사용한다. 시간 트리거나 푸시 발송 기능은 Apps Script에 넣지 않는다.

기존 게이트웨이에 `scheduler` 역할을 추가하되 다음 작업만 허용한다.

- 알림 설정 조회
- 해당 날짜와 유형의 미기록 학생 조회
- 활성 푸시 구독 조회
- 발송 결과와 중복방지 키 저장

공개, 학생, 교사, scheduler 역할의 허용 작업을 분리한다. scheduler 요청에도 기존 공유 비밀값 검증을 적용한다.

## 5. Google 시트 저장 구조

현재 스프레드시트에 세 개의 운영용 시트를 추가한다. 필요 시 Apps Script가 헤더만 안전하게 생성하며 기존 기록 시트는 변경하지 않는다.

### 5.1 `알림설정`

- 설정 버전
- 전체 활성화
- 수면 활성화
- 카페인 활성화
- 수면 알림 시각
- 카페인 알림 시각
- 주말 포함
- 반별 시작일·종료일
- 수정 시각
- 수정 주체

### 5.2 `푸시구독`

- 구독 ID: endpoint의 단방향 해시
- 역할: student 또는 teacher-test
- 학생 학번: 학생 구독에만 저장
- endpoint
- p256dh 키
- auth 키
- 수면 알림 허용
- 카페인 알림 허용
- 활성 상태
- 생성 시각
- 마지막 갱신 시각
- 마지막 성공 시각
- 마지막 오류 코드

학생 이름과 건강기록 값은 이 시트에 중복 저장하지 않는다. endpoint와 인증키는 비공개 장치 식별정보로 취급한다.

### 5.3 `알림발송로그`

- 중복방지 키
- 기준 날짜
- 알림 유형
- 학번
- 구독 ID
- 발송 시각
- 결과: success, expired, failed, skipped
- 비식별 오류 코드

endpoint, 인증키, 알림 전문은 발송로그에 기록하지 않는다.

## 6. 예약 실행과 대상 판정

### 6.1 무료 Vercel 호환 예약 방식

Vercel Hobby는 하나의 Cron 작업을 하루 한 번만 실행할 수 있으므로, 정시 슬롯별로 하루 한 번 실행되는 예약 항목을 구성한다. 각 슬롯은 실행 시 현재 한국 시간과 관리자 설정을 확인하고, 설정 시각과 일치할 때만 해당 알림을 처리한다. 이 방식은 관리자 설정을 바꿔도 재배포하지 않고 정시 단위로 적용할 수 있다.

모든 날짜 계산은 `Asia/Seoul` 기준으로 수행한다. 예약 실행이 같은 시간대에 두 번 도착할 수 있으므로 발송은 반드시 멱등하게 처리한다.

### 6.2 수면 알림 판정

한국 시간의 설정된 아침 시간대에 다음 조건을 모두 만족하면 대상이다.

1. 학생 반의 운영기간에 현재 날짜가 포함된다.
2. 주말 제외 설정과 충돌하지 않는다.
3. 학생에게 활성 푸시 구독이 있다.
4. 해당 기기의 수면 알림 설정이 켜져 있다.
5. 전날 날짜의 수면 기록이 없다.
6. 같은 기준 날짜·유형·구독에 성공 발송 기록이 없다.

### 6.3 카페인 알림 판정

한국 시간의 설정된 저녁 시간대에 다음 조건을 모두 만족하면 대상이다.

1. 학생 반의 운영기간에 현재 날짜가 포함된다.
2. 주말 제외 설정과 충돌하지 않는다.
3. 학생에게 활성 푸시 구독이 있다.
4. 해당 기기의 카페인 알림 설정이 켜져 있다.
5. 당일 카페인 기록이 없다.
6. 같은 기준 날짜·유형·구독에 성공 발송 기록이 없다.

카페인 기록에서 `섭취 안 함`도 당일 기록 존재로 처리한다.

## 7. 발송 안정성과 오류 처리

- Apps Script에서 설정이나 기록을 조회하지 못하면 알림을 보내지 않는 실패 폐쇄 방식을 사용한다.
- 각 실행에 잠금 또는 실행 키를 사용해 중복 Cron 호출이 겹치지 않도록 한다.
- Web Push가 HTTP 404 또는 410을 반환하면 구독을 비활성화한다.
- 일시적 429 또는 5xx 오류는 제한된 횟수만 재시도하고 오류 코드를 기록한다.
- 학생 한 명이 여러 활성 기기를 허용했다면 각 기기 설정에 따라 발송한다.
- 학생이 명시적으로 로그아웃하면 현재 기기의 구독을 비활성화한 뒤 세션을 삭제한다. 공유 기기에서 이전 학생의 알림이 남지 않게 한다.
- 알림 권한을 철회하거나 브라우저 데이터를 삭제하면 다음 실패 응답에서 해당 구독을 비활성화한다.
- 브라우저가 Web Push를 지원하지 않으면 설치 안내는 제공하되 알림 버튼 대신 지원 브라우저 안내를 표시한다.

## 8. 보안과 개인정보 보호

- 학생 구독 등록·변경·해제는 학생 세션으로만 허용한다.
- 교사 설정과 시험 알림은 교사 세션으로만 허용한다.
- 예약 실행은 `CRON_SECRET`을 검증한 Vercel 요청만 허용한다.
- Apps Script gateway의 역할별 허용 목록에서 불필요한 작업을 차단한다.
- 서버와 Apps Script 오류 응답에 endpoint, 인증키, 학번, 이름, 건강기록을 포함하지 않는다.
- 공개 번들 검사에 Apps Script URL, 공유 비밀값, VAPID 비밀키, CRON 비밀값 검사를 추가한다.
- 잠금화면 문구는 건강 수치나 학생 식별정보를 포함하지 않는다.
- 학생의 운영체제 알림 설정과 거부 결정을 존중하며 강제로 재허용하지 않는다.

## 9. 검증 계획

자동 테스트:

- 전날 수면과 당일 카페인 날짜 판정
- 반별 운영기간 경계일
- 주말 포함·제외
- `섭취 안 함` 완료 처리
- 학생별·기기별 알림 설정
- 같은 날짜와 유형의 중복 발송 방지
- 잘못된 학생·교사·scheduler 권한 거부
- 만료 구독 비활성화
- 실패 폐쇄 동작
- 서비스워커 알림 클릭 딥링크
- 공개 번들 비밀값 검사

실기 검증:

- 아이폰 Safari 홈 화면 추가 → 홈 화면 앱 실행 → 알림 허용 → 시험 알림 수신
- 안드로이드 Chrome 설치 → 알림 허용 → 시험 알림 수신
- 삼성 인터넷 설치·구독 지원 여부 확인과 대체 안내
- 네이버 앱 내부 브라우저에서 외부 브라우저 안내 확인
- 수면 미기록/기록 완료 각각의 발송·미발송 확인
- 카페인 미기록/`섭취 안 함` 각각의 발송·미발송 확인
- 알림 클릭 후 올바른 기록 탭 이동
- 학생 로그아웃 시 현재 기기 구독이 비활성화되고 다음 학생에게 이전 학생 알림이 발송되지 않는지 검증

## 10. 배포 순서

1. PWA Manifest, 아이콘, Service Worker와 설치 안내 UI를 추가한다.
2. Web Push 구독·설정 API와 VAPID 환경변수를 추가한다.
3. Apps Script 시트 저장·조회 작업과 역할 허용목록을 추가하고 새 버전을 배포한다.
4. 교사 설정 화면과 예약 실행 API를 추가한다.
5. 자동 테스트와 공개 번들 보안 검사를 통과시킨다.
6. 교사 시험 기기에서 푸시를 확인한다.
7. 별도 테스트 학생 기기로 미기록·기록 완료 조건을 확인한다.
8. 소수 학생 대상 설치·알림 허용 파일럿 후 전체 학생에게 안내한다.

실제 학생에게 보내는 시험 알림이나 전체 알림 활성화는 교사가 최종 설정을 저장하고 명시적으로 켠 뒤에만 수행한다.

## 11. 제외 범위

- SMS, 카카오톡, 이메일 알림
- 학생별 개별 알림 시각
- 학생 기기의 무음·진동·집중모드 강제 변경
- 네이버 앱 내부 브라우저의 백그라운드 푸시 보장
- 앱스토어 또는 플레이스토어 네이티브 앱 배포
- 알림 반응률을 이용한 학생 순위나 평가
