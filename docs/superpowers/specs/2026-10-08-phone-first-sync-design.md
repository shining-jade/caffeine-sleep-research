# 휴대폰 우선 저장과 구글시트 동기화 설계

## 목적과 승인된 방향

학생이 카페인, 수면, 체중, 목표 카페인, 목표 수면을 입력했을 때 서버 장애 때문에 기록을 잃지 않게 한다. 사용자는 2026-10-08 휴대폰에 먼저 저장하고 연결이 회복되면 구글시트로 자동 전송하는 방향을 승인했다. 이 문서는 구체적인 저장·재전송·중복 방지 동작의 검토 대상이며, 아직 구현 완료 문서가 아니다.

## 방식 선택

- 선택: IndexedDB에 원본과 전송 대기열을 함께 저장하고 기존 API를 통해 전송한다. 앱 재실행 후에도 재전송하며 실패한 요청을 확인할 수 있다.
- 대안: localStorage 대기열은 단순하지만 원자적 갱신과 여러 탭의 동시 처리에 취약하다.
- 대안: 별도 데이터베이스를 원본으로 삼으면 확장성이 좋지만 현재 운영 구조와 비용을 더 크게 변경한다. 이번에는 도입하지 않는다.

## 범위

새 카페인 기록, 새 수면 기록, 체중 및 목표 설정을 먼저 지원한다. 체중·목표 카페인·목표 취침/기상은 기존 saveInitialSetup 요청 한 건으로 저장한다. 문의·알림·교사 작업은 대기열에 넣지 않는다. 기존 기록 수정·삭제는 온라인 전용을 유지하며 명확히 안내한다. 전송되지 않은 신규 기록은 기기에서 수정할 수 있고, 수정 시 기존 대기열 항목을 대체한다.

## 휴대폰 저장

새 public/js/student-sync.js 모듈이 IndexedDB를 관리한다. 항목에는 스키마 버전, 소유자(현재 서버 세션의 studentId와 name), UUID mutationId, action, payload, 입력 시각, 상태, 시도 횟수, 마지막 오류, 서버 확인 영수증을 기록한다. 원본과 대기열 상태는 같은 트랜잭션에서 기록한다. IndexedDB 트랜잭션이 완료되어야 ‘휴대폰 저장 완료’를 보여준다. 저장 공간·브라우저 오류가 있으면 성공 메시지를 표시하지 않고 입력을 유지한다.

동기화 완료한 원본도 기기에 유지해 서버 반영 시각을 확인할 수 있게 한다. 서버에서 받은 기존 기록과 pending 항목을 학생 화면에 병합하고 mutationId/recordId로 중복 표시를 막는다. 구형 프로그램이 이미 잃어버린 입력은 이 기능으로 복원할 수 없다. 이전 페이지의 메모리·캐시에 실제 남아 있는 기록만 별도 확인할 수 있다.

휴대폰 저장은 해당 브라우저·사이트에 속한다. 브라우저 데이터 삭제, 기기 변경, 저장소 회수에는 보존을 보장하지 않는다. 지원되는 브라우저에서는 persistent storage를 요청하되 거절되어도 정상 동작한다. 자동 전송에 필요한 최초 로그인은 온라인에서 수행한다. 이미 로그인한 앱에서 연결만 끊어진 경우 기록을 보관할 수 있다.

## 승인된 보완: 즉시 전송 및 즉시 안내

사용자는 작성된 설계 검토에서 정상 연결 시 입력 직후 구글시트로 보내고, 오프라인에서는 먼저 휴대폰에 남기며 자동으로 재전송할 것을 명시했다. 휴대폰 저장 트랜잭션 직후 지연 없이 첫 전송을 시작한다. 주기적 작업은 실패한 요청의 후속 재시도에만 사용한다.

카페인과 수면 입력 직후 휴대폰에 저장된 기록(서버 반영 완료 및 pending)을 합쳐 현재 앱에 있는 기준으로 과다 섭취·수면 부족 안내를 즉시 표시한다. 서버 응답을 기다리지 않는다. 저장된 개인 목표가 없는 경우 개인 목표 초과라고 단정하지 않으며 목표 미설정 안내를 표시한다. 수면은 기기에 마지막으로 받은 연령·수면 기준을 사용한다. 서버에서 받은 동일 기록은 고유 ID로 제외하고 로컬 계산을 두 번 더하지 않는다. 이 범위의 알림은 앱 내 즉시 안내이며 OS 푸시 허가를 새로 요구하지 않는다. 브라우저를 닫았을 때의 서버 푸시와는 독립적이다.

## 전송과 화면 표시

상태는 ‘휴대폰 저장 완료 · 전송 대기’, ‘전송 중’, ‘구글시트 반영 완료’, ‘확인 필요’로 구분한다. 저장 성공 모달이 서버 실패를 숨기는 기존 분기는 제거한다. 상단/설정에 대기 건수와 ‘지금 전송’ 버튼을 둔다. 버튼은 현재 학생 소유의 미확인 요청만 전송한다. 이미 확인된 기록을 무조건 다시 추가하지 않는다.

입력 직후, 온라인 이벤트, 앱 재실행 후 세션 확인, 화면 복귀, 앱이 열린 동안의 주기적 재시도로 전송한다. 지수 백오프와 최대 간격을 두며 서버에 연속 요청하지 않는다. 휴대폰에서 앱을 닫아 둔 동안의 전송은 보장하지 않는다. 한 기기의 여러 탭은 IndexedDB 임대/재획득으로 동일 항목의 병렬 전송을 줄이고 서버의 중복 방지로 최종 보호한다.

서버가 HTTP 성공 및 실제 시트 쓰기 성공 영수증을 반환한 항목만 synced로 바꾼다. 응답이 끊겨 저장 결과를 모르면 같은 mutationId로 재시도한다. 네트워크/5xx는 대기 상태를 유지한다. 로그인 만료·사용자 변경은 자동 전송을 중단하고 다시 로그인하라고 표시한다. 유효성/충돌 오류는 ‘확인 필요’로 유지하며 입력을 삭제하지 않는다.

## 서버의 중복 방지

api/student/action.js와 Apps Script 게이트웨이에 UUID mutationId를 전달한다. action은 기존 학생 허용목록을 따르고 소유자는 클라이언트 입력을 신뢰하지 않고 서버 세션으로 확정한다. 무작위 코드가 다른 학생의 기록을 열람하거나 변경하는 인증 수단이 되어서는 안 된다.

Apps Script의 기존 쓰기 잠금 안에서 (소유자, action, mutationId)의 처리 이력을 확인한다. 기록 ID는 서버에서 안정적으로 생성하고, 재시도 시 동일 ID를 사용한다. caffeine/sleep 행에 저장된 ID를 확인해 쓰기 후 이력 저장 전에 중단되어도 재추가하지 않는다. 같은 mutationId로 다른 payload가 오면 거부한다. 처리 이력은 동기화 완료 영수증을 재반환한다.

체중·목표는 같은 학생의 info 행에 upsert하고 마지막 적용 mutationId와 수정 버전을 저장한다. 입력 당시 알려진 서버 버전보다 새로운 설정이 다른 기기에서 저장되어 있으면 오래된 대기 요청이 덮어쓰지 않도록 충돌로 표시한다. 한 기기의 여러 미전송 설정은 입력 순서를 보존하거나 최신 상태로 합치되 최초 기준 버전을 유지한다. 서버 적용과 mutationId 기록은 같은 Sheets batchUpdate 요청으로 처리한다. 운영의 native table append 수정(sheetId 포함)을 보존한다.

## 식별자와 속도

현재 로그인은 학번+이름이며 저장은 검증된 세션의 식별자로 소유자를 확정한다. 교사 화면은 시트를 일괄 조회하고 학번(비숫자 계정은 학번+이름 키)으로 연결한다. 이번 변경은 기존 시트의 식별자를 치환하지 않는다. 연구대상자코드는 연구 분석용 가명키로 별도 매핑할 수 있지만, 문자열 키를 바꾸는 것만으로 시트 전체 읽기가 줄지는 않는다. 코드 기반 로그인·데이터 이관은 별도 변경 범위다. 이번에는 중복 읽기 방지 및 기존 bootstrap/caching을 보존한다.

## 개인정보와 계정 전환

학생별 키로 기기 기록을 분리한다. 로그아웃하면 화면과 활성 메모리 상태를 지우고 전송을 중단한다. 남은 대기 기록은 다른 학생에게 표시·전송하지 않으며 동일 학생의 서버 세션을 확인한 뒤 재개한다. 로그아웃 안내에는 기기에 대기 기록이 남아 있다는 사실을 알리고, 해당 학생만 접근할 수 있는 기기 기록 정리 기능은 별도 확인을 거친다. 서버·콘솔 로그에 이름이나 건강 기록을 출력하지 않는다.

## 검증과 배포

회귀 검증: 저장 후 새로고침/재실행, 실제 오프라인 기록, 서버 502, 쓰기 완료 후 응답 유실, 동일 요청 재전송, 여러 탭, 다른 학생으로 로그인, 만료 세션, 저장소 실패, 0mg 카페인, 목표 미설정, 다른 기기의 최신 목표와 충돌을 포함한다.

최신 운영 저장소의 별도 복사본에 적용해 기존 로컬 작업을 덮어쓰지 않는다. 서버 중복 방지를 먼저 배포하고 이전 클라이언트와의 호환성을 확인한 뒤 휴대폰 저장 클라이언트를 배포한다. 실제 학생의 의료 기록을 테스트용으로 생성하지 않고 합성 테스트 데이터로 검증한다. 운영 확인에서는 동기화 상태, 대기 건수, 서버 확인 영수증과 시트 행을 대조한다.

## 관련 표시 수정

교사 목표 수면은 취침·기상이 함께 설정되지 않으면 ‘미설정’으로 표시하고 목표선을 그리지 않는다. 테스트 학생 포함/제외는 학생 목록과 설정에서도 선택할 수 있고 모든 분석 뷰를 갱신한다. 이 선택은 해당 교사 브라우저에서 유지하며 숨긴 학생 설정을 해제하지 않는다.
