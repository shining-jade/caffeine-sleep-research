## 1. 공통 원칙 [확정]

1. 피드백은 학생이 입력한 내용 안에서만 쓴다. 입력하지 않은 것을 추측하거나 일반 건강 조언을 늘어놓지 않는다.
2. 문장은 관찰로 쓴다: "기록을 보면 ~했어요". 함께 나타난 것을 원인·결과로 단정하지 않는다.
3. 보고서 본문에는 기록한 내용만 담는다. 빠진 기록은 2쪽 'E. 기록 아쉬운 점'에서만 다룬다.
4. 카페인 '안 마심(0mg)'과 '기록 없음'은 표시·계산을 구분한다. 기록 없는 날은 평균·비교에서 뺀다.
5. 비교(예: 마신 날 밤 vs 안 마신 날 밤)는 양쪽 모두 유효 기록 2일 이상일 때만 숫자를 보여 주고, 아니면 '비교 보류'와 이유를 쓴다.
6. 날짜는 그날 밤(수면 대상일) 기준. 아침 컨디션은 그 잠을 자고 일어난 다음 날 아침 기록. 아직 지나지 않은 밤은 '아직'.
7. 보고서는 5~6차시 전용이 아니라 교사가 기간을 정해 언제든 만드는 범용 보고서다.

### 학생 화면 표현 ↔ 연구 용어 [확정]

| 학생 보고서 표현 | 연구·논문 용어 | 비고 |
|---|---|---|
| 잠든 시각 | 자가보고 취침 시각 | 앱 입력 항목은 '취침 날짜·시간' |
| 일어난 시각 | 자가보고 기상 시각 | |
| 잔 시간 | 자가보고 취침~기상 간격 | 실제 총수면시간 아님. 보고서 하단에 "잠든 시각부터 일어난 시각까지" 표기 |
| 8~10시간 취침 | 청소년 권장 수면 8~10시간 충족 | Paruthi 외(2016). 범위 밖은 '짧음'/'김'으로 구분 (기존 '8시간 이상' 폐기) |
| 12시 전에 자기 | 자정 전 취침 | |
| 일일 최대 섭취량(170mg) 넘지 않기 | 일일 최대 섭취량 | 교사 설정 고정값 또는 몸무게×2.5mg(최대 400mg), `getLimit` |
| 내 목표 · 하루 150mg 넘지 않기 | 개인 목표 섭취량 | 학생 일괄 등록의 목표 칸 |
| 아침 컨디션 | 기상 후 컨디션(1~5점) | |

쓰지 않는 표현: '잠자리에 있던 시간', '어떤 날 아침 컨디션이 달랐을까', '카페인 기준 ○mg 이하', '평일 평균'.

## 2. 1쪽 · 한눈에 보기 [확정]

머리말: 이름, 기간, 수면 기록 n/n일, 카페인 기록 n/n일(안 마심 포함).

### A. 카페인과 수면
- 하루 한 칸 띠 그림(7일 기준, 기간이 길면 최근 7~14일): 낮 카페인(mg 막대 / '안 마심' / '기록 없음' / 오늘은 '오늘'), 잠든 시각(12시 넘은 날 강조), 일어난 시각, 잔 시간(막대 + 8~10시간 띠), 아침 컨디션(1~5점, 빠지면 '빠짐').
- 비교 카드 3개: 잠든 시각 평균, 잔 시간 평균, 아침 컨디션 평균 — 카페인 마신 날 밤 vs 안 마신 날 밤(일수 표시, 2일 규칙).
- 한 문장 요약 1개("기록을 보면 …").

### B. 수면을 위한 행동과 결과
- 목표 실천 달력: 일괄 등록한 개인 목표가 있으면 그 목표, 없으면 기본 기준(일일 최대 섭취량, 8~10시간 취침, 12시 전에 자기). 개인 목표가 있어도 '8~10시간 취침'은 기본 기준으로 함께 보여 줄 수 있다(시안 참고).
- 칸 표시: ✓ 지킴 · × 못 지킴 · 짧음/김(수면 시간) · – 기록 없음 · 아직.
- 지킨 날 수 / 판정 가능한 날 수.
- 한 문장 요약: 지킨 밤 vs 못 지킨 밤의 다음 날 아침 컨디션 평균(2일 규칙).
- 하단 각주: 날짜 기준, 잔 시간 정의, 비교 규칙, 일일 최대 섭취량 값, 8~10시간 근거.

## 3. 2쪽 · 자세히 보기 [확정]

### C. 카페인을 마신 날
- 섭취 기록 표: 날짜, 시각(오후 3시 이후 강조), 마신 것, 양, 마신 이유, 마신 뒤 불편함('없음'은 흐리게).
- 안 마신 날 n일(날짜), 기록 없는 날 n일(날짜).
- 한 문장 요약(예: 불편함을 적은 날의 섭취 시각과 그날 밤 잠든 시각).
- 선택지(시트 '항목'): 섭취이유 = 몸이 너무 피곤해서 / 졸음을 깨려고 / 공부나 일에 집중이 필요해서 / 스트레스나 불안을 해소하려고 / 커피나 음료 맛이 좋아서 / 습관적으로 / 운동할 때 에너지를 얻으려고 / 친구들이 마셔서. 부작용 = 가슴이 두근거렸다 / 잠이 잘 안 왔다 / 손이 떨렸다 / 속이 울렁거리거나 배가 아팠다 / 불안하거나 예민했다 / 두통이 있었다 / 없음. 표에서는 짧게 줄여 써도 된다.

### D. 수면과 생활습관
- 항목별 가로 누적 막대(숫자 = 일수): 자기 전 스마트폰(안 함/30분 미만/30~60분/60분 이상), 어제 신체활동(같은 범주), 잠들기까지 걸린 시간(15분 이내/15~30분/30~60분/60분 이상), 자다가 깬 횟수(없음/1번/2번/3회↑), 낮 졸음(없음/조금 있었음/꽤 힘들었음/매우 심했음).
- 한 문장 요약 1개: 기록이 충분할 때만 비교(예: 스마트폰 30분 이상 쓴 밤 vs 아닌 밤의 잔 시간, 2일 규칙).

### E. 기록 피드백
- 잘한 점: 꾸준히 기록한 항목·기간, '안 마심'을 남긴 날 등.
- 아쉬운 점: 카페인 기록이 빈 날(안 마셨다면 '안 마심'을 누르도록 안내), 빠진 항목(아침 컨디션, 카페인 함량, 섭취 시각), 나중에 몰아서 입력한 기록.
- '나중에 입력' 판정 [제안]: 카페인은 입력 시각(타임스탬프) 날짜가 섭취일보다 늦을 때, 수면은 입력 날짜가 기상일보다 늦을 때. 엔진이 지금 타임스탬프를 받지 않으므로 `feedbackSourceInput_`에서 함께 넘긴다.

### F. 돌아보기 [확정: 자동 피드백]
- 빈칸이 아니라 규칙 기반(기본) 또는 AI 분석(교사가 'AI 분석' 선택 시)으로 채운다. 세 칸: 잘된 점 / 어려웠던 점 / 다음 계획. 아래에 '선생님 한마디'(교사가 저장한 요약이 있으면 표시, 없으면 빈칸).
- 규칙 기반 [제안]:
  - 잘된 점: 실천율이 가장 높은 목표·기준, 또는 기록을 빠짐없이 한 항목. 예: "12시 전에 자기를 6일 중 5일 지켰어요."
  - 어려웠던 점: 실천율이 가장 낮은 목표와, 못 지킨 날 함께 기록된 사실 1개(그날 카페인 시각, 스마트폰 사용 등). 원인으로 단정하지 않는다. 예: "8~10시간 취침은 6일 중 2일이었어요. 짧았던 3일 중 2일은 자기 전 스마트폰을 30분 넘게 썼어요."
  - 다음 계획: 실천율이 가장 낮은 목표에 대한 작은 행동 하나. 학생 기록에서 지킨 날의 모습을 근거로 쓴다. 예: "8~10시간 잔 날처럼 23시 30분 전에 누워 보기."
- AI 분석 [제안]: 규칙 기반이 계산한 사실(JSON)만 입력으로 주고, AI는 문장만 다듬는다. 새 사실·숫자·진단·의학적 조언 추가 금지. 실패하면 규칙 기반 문장으로 대체(기존 `aiFallback` 흐름 사용).

## 4. 디자인 [확정: 시안 그대로]

- 시안 원본: `docs/design/report-redesign/Main.dc.html`(1쪽), `Page2.dc.html`(2쪽). Design 캔버스 형식이라 `{{…}}`·`<sc-for>`는 템플릿 문법이다. 마크업·인라인 스타일·`renderVals()`의 가짜 자료와 색 규칙을 그대로 옮기면 된다.
- 판형: A4 세로, 794×1123px(96dpi) 페이지 2장, 안쪽 여백 36px 44px 28px.
- 글꼴: Noto Sans KR 400/500/700/800. 이미지로 찍을 때 글꼴이 다 불러와진 뒤 찍는다(`document.fonts.ready`). 가능하면 woff2를 앱에 직접 포함 [제안].
- 글자 크기: 제목 26px, 영역 제목 17px, 본문·요약 문장 13~14px, 보조 설명 11px, 각주 10.5px. 기존 PDF의 11px 본문보다 키운다.
- 색: 강조 보라 #5B4FC4, 본문 #1F2A44, 보조 #4A5470, 카페인 #D98A55(글자 #7A3A12), 잔 시간 범위 안 #3F72BD / 범위 밖 #A9C0E6, 8~10시간 띠 #DFE8F7, ✓ #2F7D62 바탕 흰 글자, ×·짧음 흰 바탕 #D0743F 테두리, 김 #8A7FD0 테두리, 기록 없음 #EEF0F4, 아직 점선 #B8BCCB. 컨디션 1~2 #FBE0D0/#7A2E0B, 3 #EBE8F7/#33296F, 4~5 #D6EFE4/#185A41. 요약 문장 상자: 카페인 #FFF4E9, 수면·행동 #EEF6F2, 생활습관 #EEF3FA.
- 피할 것: 카드 왼쪽 굵은 테두리, 이모지, 글자만 빽빽한 카드.

## 5. 출력 방식 [확정: 이미지]

현재: 보고서 HTML → Apps Script `getAs(MimeType.PDF)`(`makeTeacherReportPdf_`) → 글꼴·CSS·SVG 처리가 약해 흐리고 깨짐.

바꿀 방식 [제안]:
1. 교사 브라우저에서 보고서 HTML(2쪽)을 화면 밖에 그린 뒤 페이지별로 이미지화(html-to-image 또는 html2canvas, 배율 2, JPEG 품질 약 0.85 / 필요 시 PNG). 라이브러리는 정확한 버전으로 고정.
2. 교사 '저장': 이미지 2장(PNG/JPEG) 저장, 또는 두 이미지를 넣은 PDF(jsPDF 등) 저장. 일괄 저장은 학생을 한 명씩 순서대로 그려 ZIP(`createPdfZip` 재사용).
3. 메시지로 보내기 [확정: 이미지 방식]: 브라우저가 만든 '이미지 PDF'를 base64로 보내고, `sendPrivateTeacherReport`가 html 대신 이 PDF를 받아 기존처럼 비공개 Drive 파일 + `teacher_messages`(유형 `privatePdf`)로 저장한다. 학생 열람 경로(`/api` report 핸들러, `downloadStudentReportPdf`)는 바꾸지 않아도 된다. 서버 검증: `%PDF-` 시작, `REPORT_PDF_LIMIT_`(3MB) 이하. Vercel 요청 본문 크기 제한(약 4.5MB)도 고려해 JPEG로 용량을 줄인다.
4. 기존 html → PDF 경로(`renderTeacherReportPdf`)는 당분간 남겨 두되 화면에서 쓰지 않는다.

## 6. 확인 방법

- 테스트 학생(학번 0)과 가짜 자료로만 확인한다. 실제 학생 기록은 열거나 외부에 보내지 않는다.
- 경계 사례: 카페인 안 마심 / 기록 없음 / 오늘(아직), 12시 넘어 취침, 컨디션 빠짐, 한쪽 1일뿐인 비교(비교 보류), 개인 목표 있음·없음, 기간 7일·14일.
- 수정 전후 화면 이미지를 연구자에게 보여 주고 확인받은 뒤 커밋한다. 배포는 별도 결정.
- 변경이 연구 중 학생에게 보이는 피드백을 바꾸므로, 배포 시 날짜와 버전을 `docs/sleep-date-policy.md` 변경 이력과 개발 이력에 남긴다.
